# Published release download verification

Official HACS 2.0.5 in the isolated Home Assistant 2026.9.4 instance downloaded the GitHub successor release `v0.2.0` through `hacs/repository/download`. The existing local test controller folder was preserved outside `apps` before the download. HACS reported `installed: true`, `installed_version: v0.2.0`, `available_version: v0.2.0`, and destination `/config/appdaemon/apps/Zendure-AppDaemon-Proxy` for repository ID `1402331836`.

Every installed root file matched the published archive byte for byte: sixteen Python modules, `LICENSE`, and `NOTICE`. The archive SHA-256 was `21c8c333c74fad0731d267dad4bf7e1aa83ec49ec2ceeeb85e2ed7037c231f67`. After an actual host AppDaemon 4.5.13 restart with `production_mode: true`, the HACS-installed controller returned HTTP 200, `v0.2.0`, and `3x Zendure via PROXY` from the synthetic three-device report. The metrics, logs and diagnostics routes returned HTTP 200. All three HA device-health sensors reported `Healthy`; the version sensor reported `v0.2.0`. The GET counter restored its previous value and reached 73 after the new report.

The first download request found the custom repository registration missing after an earlier isolated HA restart. Re-adding the same successor repository through `hacs/repositories/add` restored the registration; the subsequent release download succeeded. The failure occurred before files were downloaded and did not change the successor archive. After successful installation, both HACS `hacs.repositories` and `hacs.data` storage files contained the successor repository ID and name. Persistence was checked in the saved storage files; another HA restart was not performed. Existing user installations were unchanged.

The previously recorded local archive rehearsal is in `audit/rehearsal.md`. The published download result completes that rehearsal's pending GitHub-download check. Local machine-readable HACS state, installed-file hashes and the resulting report remain in ignored `build/sandbox/hacs-6540a49fe8/` as `hacs-installed-info.json`, `hacs-installed-files.json`, and `hacs-downloaded-report.json`. Credentials remain outside audit artifacts.

An additional check executed the official HA 2026.9.4 `HistoryStats._async_compute_seconds_and_changes` method with synthetic histories in the isolated container. An ongoing matching interval that began before the day window counted once at the window start and one second afterward when the minimum duration was zero. Leaving and re-entering the matching state counted twice. The relay example's `type: count` represents matching recorded intervals, including an ongoing interval; an exact physical relay-edge count requires a different measurement. No production Recorder history was read.
